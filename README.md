# NLB shared view

A tiny, private web page that shows two (up to five) people's own NLB seat and room bookings for
**Today and Tomorrow** side by side, so you don't book the same room twice or sit in separate seats
when one of you already has a room.

> **Not affiliated with, endorsed by, or connected to the National Library Board (NLB) Singapore.**
> This is an unofficial personal tool. It is read-only: it never books, cancels or checks in anything.

## How it works

```
 your browser, on the NLB page (logged in)                    your own Cloudflare account
┌──────────────────────────────────────────┐   bookings     ┌──────────────────────────────┐
│ bookmarklet (one tap)  or  userscript     │ ─────────────► │ Worker + one Durable Object  │
│ reads YOUR bookings from the NLB page,    │   only         │ stores the latest snapshot   │
│ strips everything but booking fields      │                │ per person (no history)      │
└──────────────────────────────────────────┘                └──────────────┬───────────────┘
                                                                            │ JSON
                                       secret page  /v/<view secret>  ◄─────┘ (polled every 5 s while visible)
```

- Each person pushes their **own** bookings from their own logged-in NLB page. A push replaces
  that person's previous snapshot.
- The page shows a timeline per day with one lane per person, merges NLB's hourly rows into one
  block, shows rooms across both lanes, flags overlaps (including "possibly redundant" seats inside
  a partner's room and duplicate rooms), and tells you how fresh each person's data is.
- A booking NLB would auto-cancel (no check-in 15 minutes after the start) and that has not been
  re-pushed since shows an **unverified** badge.
- All times are Singapore time, whatever your device's time zone.

## Privacy model

- **The server never contacts NLB** and stores no NLB password, cookie or token. There is no
  `fetch()` anywhere in the Worker (this is covered by tests).
- A push contains **booking rows only**, trimmed on your own page to ten whitelisted fields
  (reference, seat/room, library, area, floor, start, end, actions, and the room-info text). Your
  name, email, member/account ids and quota data are never sent, and visit or day-pass bookings are
  excluded. The Worker ignores any other key, then keeps only the fields it needs: the room-info text
  (which includes the booking purpose you typed) travels in the request but only the room's pax is
  stored. There is no timestamp from your device; the server stamps the time it received the push.
- **Nothing deployment-specific is in this repository**: no URL, no names, no secrets.
  `npm run init-secrets` generates a view secret and per-person push tokens (256-bit) and stores them as
  Worker secrets in *your* Cloudflare account. The bookmarklet and userscript are generated by the
  Worker at `/setup/<view secret>` with your origin and your token filled in.
- The view link is **read-only**. A push token can only replace its own owner's snapshot, and the
  view secret cannot be used as a push token.
- Every response carries `X-Robots-Tag: noindex, nofollow, noarchive` and `Referrer-Policy: no-referrer`;
  `/robots.txt` disallows everything; the root, unknown paths and wrong secrets all return the same
  bare 404; the pages load nothing from third parties and are served with a strict CSP.
- Stored data: the latest snapshot per person only (no history).

## Deploy (free tier)

You need Node.js 20+, and a free [Cloudflare](https://dash.cloudflare.com/sign-up) account.

```sh
npm install
npx wrangler login
npm run init-secrets -- Alice Bob      # your display names (2 to 5); or run without names to be prompted
npm run deploy                         # builds, then deploys; prints your https://nlb-shared-view.<you>.workers.dev URL
```

`init-secrets` generates the secrets, installs them into your Cloudflare account (piped to
`wrangler secret put` over stdin, so they never appear on a command line), writes a git-ignored
`.dev.vars` for local development, and prints your private setup address:

```
https://<your workers.dev URL>/setup/<view secret>
```

Pass `--url=https://nlb-shared-view.<you>.workers.dev` to have it print the full address. Lost it?
The view secret is in your `.dev.vars` (`VIEW_SECRET=`); Cloudflare does not let you read secrets back.

Open the setup page, then each person installs their own push client (below). The shared page is at
`https://<your workers.dev URL>/v/<view secret>`. Bookmark it, but see the leak caveats first.

### Local development

```sh
npm run init-secrets -- Alice Bob --local-only   # writes .dev.vars only
npm run dev                                      # http://localhost:8787/setup/<VIEW_SECRET from .dev.vars>
```

## Install your push client

Do this on the setup page, in your own section (it is pre-filled with your push token). Log in to NLB
and open **My Bookings** before pushing.

### Bookmarklet (one tap)

- **Desktop (Chrome/Edge/Firefox):** show the bookmarks bar and **drag** the "Push my NLB bookings"
  button onto it. On the NLB My Bookings page, click that bookmark. A new tab opens on the shared
  view. If you aren't logged in, an alert says "Log in to NLB first" and nothing is sent. The
  bookmarklet is deliberately tiny (under 1,000 bytes) because Android Chrome truncates long
  bookmark URLs.
- **Android (Chrome):** tap **Copy bookmarklet** on the setup page. Bookmark any page, then edit the
  bookmark: set the name (for example "Push NLB"), and as the URL type `javascript:` and then paste
  the rest (Chrome strips a leading `javascript:` when you paste). To run it, open the NLB My
  Bookings page, type the bookmark's name in the address bar and tap the suggestion with the bookmark
  icon. (Chrome on Android won't run a bookmarklet from the bookmarks list.)

### Userscript (automatic pushes)

Pushes once when you open NLB and again a few seconds after your bookings change, and shows a small
"pushed ✓" toast.

- **Desktop:** install [Violentmonkey](https://violentmonkey.github.io/) or Tampermonkey, then click
  **Install the userscript** on the setup page and confirm. The script is limited to
  `https://www.nlb.gov.sg/seatbooking/*` and may only talk to your Worker (`@connect`).
- **Android:** Chrome has no userscript managers. Use **Firefox + Violentmonkey**, open the setup
  page in Firefox and tap **Install the userscript**.

The userscript updates itself from its own setup address (`@updateURL`).

## Leak caveats (treat the view link like a password)

Anyone holding the **view link** can read everyone's bookings (they can't change anything). Anyone
holding your **bookmarklet or userscript** can overwrite *your* snapshot (and nothing else).

- **Screenshots, screen-sharing and chat link previews** of the setup page, the view page URL or the
  userscript file expose these secrets. Don't post them.
- **Synced browser history and bookmarks** (Chrome/Firefox sync, other devices, shared computers) will
  contain the view URL (`/v/<secret>`, also the redirect after a bookmarklet push) and your bookmarklet
  (which embeds your push token). Use a profile you trust, or clear them.
- The userscript's update address contains the view secret.
- The page sends no Referer and is not indexed by search engines, but a secret in a URL is still a
  secret that you handle.
- Cloudflare can see traffic to your own Worker, like any host.

## Rotate secrets

Re-run `npm run init-secrets -- Alice Bob` (add `--force` to refresh `.dev.vars`). It generates a new
view secret and new push tokens and replaces the old ones immediately: old view links, bookmarklets
and userscripts stop working (they get a plain 404). Then open the new setup address and reinstall the
bookmarklets/userscripts. No redeploy is needed.

```sh
npm test            # builds the browser bundles, then unit + Worker tests
npm run typecheck
```

`scripts/` build and `init-secrets` · `docs/` architecture intent and implementation maps ·
